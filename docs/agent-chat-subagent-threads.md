# Sub-agent Threads And Chat Relationships

This page inventories what T3 Code (`reference_projects/t3code`, read at `origin/main` `071239804e`) offers around provider-native sub-agent threads and the relationships between threads, and maps each item to Alera. Items Alera does not implement say exactly why.

## Inventory

| Item | T3 Code | Alera |
| --- | --- | --- |
| Native sub-agent as its own thread | `OrchestrationV2Subagent` records with `childThreadId`; the child is an app thread with `lineage.relationshipToParent: subagent` and `creationSource: provider` (`isProviderNativeSubagentThread`), which takes no messages | Implemented with a different storage: the sub-agent's items stay in the parent chat under the call that started it (`normalized.parentItemId`, `normalized.subagent`), and `agentChat.subagent` reads them as the sub-agent's own transcript. Live work arrives through the parent chat's changes. A sub-agent is never a chat, so it can never receive a message. |
| Codex child transcript | Child thread notifications (`item/*`, deltas with the child's `threadId`) projected into the child thread | Implemented: the Codex provider streams a child's own items and deltas as items of the session, linked through `parentToolUseId` to the call that spawned it (first call that names the child wins); the child's prompt stays on that call. Grandchildren nest the same way. |
| Claude child transcript | Items with `parent_tool_use_id` projected into the child thread | Implemented: already streamed under the Task call; now readable on its own. |
| Sub-agent model, effort and timing | `model`, `modelSelection`, `startedAt`, `completedAt` on the record | Implemented: `normalized.subagent.model`, `reasoningEffort`, `startedAt`, `completedAt`. Codex takes model and effort from the spawn; Claude falls back to the Task tool's `model` input. |
| Opening a sub-agent | Web route to the child thread; mobile thread screen | Implemented: desktop opens it in place of the chat inside the same tab, keeping the chat mounted underneath (scroll and composer survive); the phone pushes a screen. Both are explicit presses. |
| Sub-agent bar instead of the composer | `ProviderSubagentBar` (web and mobile): provider icon, model, effort, live status timer, "Runs on its own", Open Parent | Implemented on both (`AgentChatSubagentBar`). Open Parent returns to the chat, or to the sub-agent that started a nested one. |
| Status label | `formatProviderSubagentStatus`: "Working 1m 5s", "Completed in 42s", else the label | Implemented as `agentChatSubagentStatusLabel` in `alera_agent_chat`. |
| Stopping one sub-agent | `stopSubagent` adapter method; Claude only (`query.stopTask`) with a strong native task ref; app-owned children stop through their turn | Implemented for Claude (`stop_task` for a running non-command task) and for Codex (`turn/interrupt` on the child thread's running turn), behind `agentChat.stopSubagent` and the session capability `stopSubagent`. Delegated chats keep Chat Tasks cancel. |
| Relationships control | `ThreadRelationshipsControl`: parent, fork and sub-agent edges, related, active and folded Previous Agents groups, Show N More paging, running and failed counts, open, stop, merge-back split button | Implemented as Lineage: a control over the desktop chat and a sheet from the phone tab's actions. It lists the parent chat (delegation), the fork source, forks, delegated chats and native sub-agents with the same grouping, paging and counts, and opens, stops and merges back. Rows show kind and status instead of T3's hover card (`SubagentTooltipContent`); the opened sub-agent shows its model, effort and result. |
| Context transfer edges | `contextTransfers` drawn as transfer rows | Not as edges: Alera records no transfer objects. A merge-back appears as a notice in the receiving chat's timeline. |
| Merge-back | `thread.merge_back`: a pending context transfer of the fork's delta, injected as a `fork_delta_summary` handoff into the source's next run, then navigation to the source | Implemented as `agentChat.mergeBack`: the fork's own prompts and answers after the fork point become a pending notice in the source chat, carried ahead of the next message as background context. Nothing runs at once. The answer names the source chat; the client does not navigate on its own. |
| Workflows | `ThreadLineageWorkflowRow`, `deriveWorkflowGroups`, `stopWorkflow` over Claude `local_workflow` telemetry (phases, agents, run handles) | Not implemented; see below. |
| Workspace breadcrumb | `WorkspaceBreadcrumb`: project and branch or worktree of the thread | Partly: the desktop sub-agent header reads chat › sub-agent. The workbench already names the workspace and branch around the tab, so no second breadcrumb is drawn. |
| Running sub-agent pill | `resolveSubagentPillSegment` ("2/3") in the thread header | Implemented as the running count on the Lineage control and its heading ("Lineage · 2 running"). |
| ACP native child sessions | Claude ACP `subagent_update` and `session_message` child sessions, projected and resumable (commit `6958838214`) | Not implemented; see below. |
| ACP flavor sub-agents | Devin, Copilot, Antigravity tool-based sub-agents | Unchanged: Devin and Copilot already map their sub-agents to task events and Copilot links items to the Task call, so those open like any other; Devin items carry no call link. |

## How Alera Serves It

- Providers: `Provider::stop_subagent` (default `Unsupported`), the Codex child item stream and the Claude `stop_task` path. See [Rust Agent Providers](rust-agent-providers.md).
- Runtime: `agentChat.subagent` and `agentChat.stopSubagent` under `agentChatSubagentThreadsV1`, `agentChat.mergeBack` under `agentChatMergeBackV1`, both advertised in the control file, `status.get` and `mobile.hello`, and allowed for phones. `agentChat.list` and snapshot lineage name `forkedFromChatId`. See the runtime [readme](../rust/alera-cli/src/terminal_host/server/agent_chat_runtime/readme.md).
- Package: `AgentChatSubagentTranscript`, `agentChatSubagentDescendants`, `AgentChatSubagentTimeline`, `agentChatSubagentStatusLabel` and `AgentChatRelationships`, plus `subagent`, `stopSubagent` and `mergeBack` on the lifecycle repository.
- Clients feature-detect both capabilities; an older runtime keeps sub-agents inline with no Open or Stop and no Merge Back.

## Not Implemented

- **Workflows.** T3 reads Claude Code's undocumented `local_workflow` task telemetry (`workflow_name`, phases, per-agent prompts, results and run handles in `task_progress`) into workflow groups with phase rows and a Stop Workflow command. Alera's Claude adapter projects a workflow task as one sub-agent like any other task, so it opens, shows its work and stops through `stop_task`, but the phases and member agents are not modelled: there is no stable SDK contract for that telemetry to port, and a guessed shape would misreport phases.
- **ACP native child sessions.** T3 projects them only for the Claude ACP agent run with `CLAUDE_AGENT_ACP_EXPERIMENTAL_V2=1`, which switches it to ACP protocol version 2: turns are driven by `state_update` instead of the prompt response, prompts answer with message ids, and child sessions report through `subagent_update` and `session_message`. Alera runs registry agents on the stable protocol, where that agent reports none of these, and drops notifications for other sessions. Porting the child sessions first needs Alera's ACP adapter to adopt that experimental protocol, a separate change with its own fixtures.
- **Hover cards and context transfer rows**, as listed above.
- **CLI and MCP.** T3 exposes merge-back and workflow stop as MCP tools. Alera adds no `alera agent-chat` command or MCP tool for sub-agents or merge-back in this change, so the CLI and MCP skills are unchanged; the human surface is the desktop and phone UI.
