# Performance And Stability Audit

## Scope And Success Criteria

Audit desktop Flutter, the shared Rust runtime, the mobile companion, the cloud backend and edge relay, and the landing site. Fix reproducible correctness, lifecycle, bounded-resource and responsiveness problems without changing product contracts or unrelated behavior. Every fix must have evidence and relevant validation. Deliver the implemented changes and a reviewable report. The user initially withdrew deployment and publication authorization. The subsequent PR #888 request explicitly authorizes fixing seven selected review threads and pushing the fixes, then resolving each thread after its fix is pushed. Do not manually merge, deploy or publish; the runtime watch owns merging when eligible.

## Design And Assumptions

Prefer eliminating unnecessary work, bounding queues, cancelling obsolete work and disposing resources within the existing architecture. Preserve protocol versions and compatibility unless a demonstrated problem requires a coordinated change. Use Flutter 3.47.2 and Dart 3.13.2, the pinned Rust toolchain, lockfiles and source submodule revisions. Timing claims require comparable measurements; code inspection alone does not establish a speedup. Keep implementation and validation in local or isolated native-build environments. External deployment configuration is excluded by the user's instruction.

## Expanded Architecture Work

The user asked to incorporate the three previously deferred architecture items. Accepted terminal history must retain byte order and survive a successful graceful shutdown; storage failures must be surfaced, and capacity exhaustion must apply backpressure rather than silently discard accepted data. Command admission must be bounded without actor self-send deadlocks or losing shutdown/control operations. General process capture must limit combined stdout/stderr, terminate and reap on excess, preserve decoding and support justified large-output callers. Archive staging must run outside the UI isolate, cancel before returning a stale stage, remove only owned partial files, preserve traversal/symlink/hash/signature defenses and route subprocesses through the app's injectable native boundary. Root owns app integration and final generation/validation; separate workers own runtime admission/history, process capture and the local dependency API. No protocol, product behavior or release contract should change beyond documented resource-overload errors. The final Windows debug build validates the expanded source at code commit 3958cef7d; all 526 source hashes and both artifact hashes are recorded separately.

## Findings And Evidence

### Runtime Snapshot Watchers

The initial snapshot and retry reads bypassed the change coalescer's in-flight protection. An event could start a second read while the first was pending, allowing an old snapshot to overwrite newer state. A cancelled subscription also left its controller open: a pending read that failed after cancellation started a fresh retry loop with no consumer. A successful event refresh did not cancel an earlier failure's retry timer.

Snapshot reads now run one at a time, collapse pending refresh requests, cancel obsolete retry timers and stop publishing or retrying after cancellation. The focused suite passes all 14 tests, including five new deterministic regressions for overlap, obsolete retries and cancellation during initial/event reads. Running that same suite against the original source fails four regressions; the cancelled-read cases grow from 1 or 2 reads to 14 or 15 reads within a simulated minute. No protocol or generated interface changes are involved.

### Mobile Transport And Workspace Lists

Malformed WebSocket messages previously threw from the stream's data callback, bypassing its error handler and leaving requests pending until timeout. They now fail the transport and pending requests immediately so the existing reconnect flow can recover. Workspace attention is indexed once per snapshot rather than scanned once per workspace; the refresh changes from O(workspaces x agents) to linear passes. Final mobile code generation, EOF normalization, formatting and analysis pass. The full mobile suite passes 836 tests; four existing integration cases require an isolated-test sidecar or the edge relay fixture and are skipped in that default run. Those fixtures were then run separately against the fresh native binary: recovery, normal relay and adversarial relay all pass, totaling six additional successful test executions. Eighteen shared configuration tests also pass. No generated interfaces changed.

The synthetic attention benchmark uses two warmups, five alternating samples per size, output equality and checksums. At 1,024 workspaces and 4,096 agent states, median calculation time fell from 24,965 to 497 microseconds on this machine; at eight workspaces both paths measured approximately 33-34 microseconds. This compares the algorithms and does not establish end-to-end latency on a phone. The benchmark is reproducible with `dart run tool/mobile_attention_benchmark.dart --output <path>` from `mobile/`. Raw samples, medians and median absolute deviations are retained in [the benchmark capture](audit-mobile-attention-2026-10-02.json).

### Diagnostics And Logging

Logging previously retained an unbounded chain of writes during error storms and did not handle asynchronous `IOSink.done` failures. Pending records now have a 256 KiB budget, flush in 64 KiB batches and safely disable a failing sink. Dynamic strings are capped at 8,192 UTF-16 code units before regex redaction and JSON serialization; oversized fields are omitted completely rather than partially exposing a secret. Oversized records and old pending records are deliberately discarded under overload because logging is best effort. Diagnostic files are read asynchronously and ZIP compression runs in an isolate, keeping compression off the UI isolate. Focused tests exercise a non-writable path, asynchronous `/dev/full` failure, bursts and missing rotated files. A custom object's `toString()` remains arbitrary work before its returned string can be limited.

### Runtime, Hooks And Agent Output

Process stdin is bounded to 8 MiB and 64 writes on Dart and 4 MiB and 32 queued items on Rust. Dart writes use 256 KiB chunks and bounded adaptive retries; overflow, closed stdin and bridge failures become visible process errors followed by termination and reaping. Late native events are ignored after terminal failure or exit. Hook queues have 256 event slots and return retryable 429/503 under pressure; receiver transitions are serialized and old subscription generations are ignored. ConPTY uses a bounded 16-event channel, and blocking workspace file requests have four shared permits.

AI output has a combined 4 MiB budget and runtime proxy output a combined 1 MiB budget, with incremental UTF-8 decoding and cleanup on timeout, malformed output or stream errors. Quota cache writes carry generations so a late request cannot undo invalidation. Codex initial scans read the last 256 KiB, subsequent scans cap work at 1 MiB in 64 KiB chunks, long lines are rejected, and background polling parks with the application. A shortened/recreated transcript resets its cursor and decoder. Every asynchronous scan validates its watch generation before decoding or emitting, including after replacement during an in-flight read.

### Cloud Delivery And Online Indexes

FCM delivery uses at most four concurrent sends inside a 12-second request budget, with time reserved for persistence. Pending attempts are claimed atomically, every reclaimed lease receives a new UUID, and only the current lease can finalize. Duplicate lookup is account-scoped while retaining global runtime/event idempotency. A transferred runtime cannot replay the former account's event payload. The delivery contract covers two concurrent stale reclaims and owner transfer. FCM remains best effort: an acknowledged send followed by a crash before persistence can be duplicated.

Required schema migrations 0001-0004 are validated before bind, including checksums and rejection of unclassified versions. The 16 additive indexes in 0005-0020 run in a single background task after bind, with non-blocking advisory-lock polling limited to 30 seconds and 15 minutes per index operation. Interrupted invalid indexes are repaired without rewriting migration checksums or clearing dirty metadata. Required-schema readiness is independent of a held online-index lock. Online work may need a later startup or guarded operator phase under CPU throttling. Isolated PostgreSQL contracts and EXPLAIN confirm recovery and valid index use; no production migration was executed.

### Updater Transport

Metadata responses have a 1 MiB cap and 20-second timeout. Artifact transport enforces the signed byte length and 30-second header/idle-gap limits, aborts the socket on cancellation or overload and closes downstream streams before waiting for upstream cancellation. Disposal during completion cannot return a stale staging path. Cleanup checks owned staging prefixes, rejects symlink roots and verifies canonical containment inside system temporary storage. Local `file:` artifacts bypass the HTTP boundary but use the same extraction boundary.

The expanded scope uses a local MIT fork of `desktop_updater` 2.7.0 with optional public cancellation, operation runner, cleanup runner and file-mode parameters. ZIP input/output streaming and filesystem mutations execute synchronously inside a worker isolate, keeping them off the UI isolate; cancellation waits for actual worker exit before stage cleanup. The app supplies the native process runner and a POSIX chmod syscall. macOS stages use owned DMG mountpoints and a cancellation-independent cleanup runner, including forced detach only for an owned mount. Cleanup failures are logged without replacing the original operation failure. Hash/signature checks, traversal protections and ancestor symlink checks remain enforced. Signed macOS bundles retain their trusted `ditto` handling of internal symlinks. Decoder memory can scale with archive contents inside the worker; streamed I/O does not establish a constant-memory archive guarantee. Default package runners cannot cancel an active process, so Alera injects its token-aware adapter. Stale stage sweeps, hashing and PKG metadata parsing retain a cooperative cancellation boundary. The full vendored suite passes 446 tests with 10 environment-dependent skips, analyzer has no errors and 376 info-level findings under upstream lint settings, and 180 files are formatted. App cleanup/backend/adapter tests pass 26 cases with clean targeted analysis. Three separate Mac VM cases exercise facade cancellation during copy, exit waiting and normal/forced detach using fake processes; source hashes match and no native app or installer is launched.

### Explorer And Editor State

Explorer refreshes now guard both workspace/mode generations and individual native projections, preventing late results from restoring an old tree. Watcher transitions are serialized and bursts are coalesced instead of extending an unbounded Future chain. Regression cases cover 100 events, same-workspace projections completing out of order and a workspace switch during watcher shutdown. Editor chrome refreshes only when the document changes between clean and dirty; repeated keystrokes while already dirty avoid rebuilding the surrounding surface. Save and discard are blocked while an autosave conflict is being resolved, preventing overlapping writes and duplicate conflict dialogs. The final VM suite passes, and both editor regressions pass against a real Linux native build under Xvfb. ### Expanded Runtime Validation

Runtime admission and ordered history writes are complete in b35966c88 and fbb360f5e. Work admission allows 256 commands and 64 MiB; controls allow 128 commands and 16 MiB. Client lines up to 1 MiB use controls, and larger lines use work capacity, preserving valid base64 dictation audio up to the existing 25 MiB audio contract. The encrypted relay envelope limit remains 1 MiB. Readers wait for capacity in order; relay peers reserve a control slot for cancellation cleanup. One serial writer accepts at most eight 64 KiB batches per session and retains completion copies. Exact repeated writes are idempotent; conflicting data at the same sequence is an error. Checkpoint metadata and retention trims run behind the history barrier outside the actor. Capacity or storage failures preserve FIFO data and pause the producer. Close requests retry asynchronously with at most 32 pending requests and 1 MiB per retained request; each session has one outstanding timer of each history kind, including across generation changes. Owner lifecycle records are created only after history is ready. Shutdown preserves the first exit intent and remains resumable while storage is pending. Oversized JSON completion payloads return a bounded error with the request identity. Remote retirement captures local transport identities before the owner closes them and transfers those guards through final preparation and history retry, retaining strict PID/start-time/session verification. Preparation reports no closed tabs; completion reports actual tab ids. Pinned Rust CI passes 2,860 tests with 5 opt-in skips in 25 suites; Clippy with warnings as errors passes. Cold-start, protocol-close, async-future layout, checkpoint-fixture and remote-retirement races are repaired and validated. Evidence is in [audit-runtime-validation-2026-10-02.json](audit-runtime-validation-2026-10-02.json). Forced termination or power loss can still lose unpersisted bytes; permanent storage failure intentionally prevents successful graceful teardown.
