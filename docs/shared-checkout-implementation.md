# Shared Checkout Workspaces

## Objective

Implement the approved shared-checkout workspace model across the runtime, desktop, mobile and CLI, including SSH, automations and identity-preserving relocation. A workspace owns task state, not the project directory. Only linked worktrees retain exclusive workspace ownership. The later user instruction authorizes delivery after implementation and review: create a branch and commit, fetch all remotes with pruning, merge remote main into the branch, resolve conflicts, create and validate the pull request, merge it, synchronize local main and remove the PR branch, then complete Cut Release through its version pull request and verify publication. Further precheck migration and integration evidence is tracked in [Shared Checkout Precheck Validation](shared-checkout-precheck-validation.md).

## Accepted Behavior

- Projects may have zero workspaces. Registering a new project creates its first ordinary workspace; reconciliation never recreates a deleted workspace.
- New Workspace and From Prompt default to the project checkout, fresh task state, task naming and no Parent. Folder projects support the same shared behavior without Git.
- Existing IDs, instance IDs, names, tabs, history, explicit pins and relationships survive migration. Remove Default / Non-Default filters and preferential ordering, retaining location indicators.
- Files, branch and index belong to the checkout; agents, tabs and unsaved buffers belong to tasks. Permit concurrent agents. Warn before shared branch changes and detect external modifications before saving.
- Removing a shared task preserves files and other tasks. Resolve unsaved buffers with Save, Discard or Cancel. Offer pausing dependent automations and cancelling their runs. Verify owned process shutdown.
- Hand Off / Hand On change the same workspace's location. New-branch Hand Off preserves the source branch; transferring the current branch requires an explicit replacement. Offer leaving changes or moving all transferable changes when safe. Hand On requires a clean destination and no affected dirty buffers, permits other active agents with confirmation, and removes the old linked worktree after success. Block processes that cannot relocate reliably. Persist recovery phases.
- Register or clone one project checkout per SSH host. New linked worktrees use that remote repository. Preserve legacy remote worktrees. Relocate only within a host; do not synchronize machines automatically.
- A new automation target references project and host, creates one workspace per run, uses the current checkout state and preserves its workspace by default. Optional success cleanup removes only task state and processes, never shared files.
- Setup applies to newly created linked worktrees, not to new tasks on an existing checkout. Preserve current mobile Git and SSH editor write limitations.
- Incompatible clients must update before incompatible mutations. Preserve live terminals and independent terminal protocols. Missing folders or unreachable hosts retain workspace records.
