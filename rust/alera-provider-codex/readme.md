# provider adapter scope

This crate maps the shared provider contract to the app-server JSONL boundary. Host-owned MCP servers are projected into `thread/start`, `thread/resume` and `thread/fork` as one dotted `config["mcp_servers.<name>"]` key per server: stdio uses `command`, `args`, and `env`, while HTTP uses `url` and `http_headers`. Codex writes a request override at its final path segment, so a whole `mcp_servers` table would replace the servers Codex was launched with (`codex app-server -c mcp_servers.x.command=...`); a dotted key adds only its own server. The nested `config.mcp_servers` table is used instead when the caller already sends that table, or when a server name contains a `.`, which Codex would split into a path.

Every thread request also sends `config["tools.update_plan.enabled"] = true`, because Codex 0.152 made the `update_plan` checklist tool opt-in and a turn without it never reports plan progress, and `config.mcp_optional_startup_grace_ms = 10000`, so Codex waits up to 10 s instead of 1 s for MCP servers before the first model request. A caller value for either setting wins: any dotted `tools.update_plan` key or nested `tools.update_plan` entry keeps update_plan as given, and a nested caller `tools` table receives `update_plan` inside it.

Injected server names cannot replace caller-owned entries, whether the caller names them in a nested table or with dotted `mcp_servers.<name>` keys. The native boundary does not represent a stdio working directory, so a spec that supplies one is rejected before a native request is sent. Secret environment values and headers are passed to the native process but are not copied into provider events or debug output.

The MCP projection is covered by transport-backed lifecycle tests for new and resumed threads, collisions, and unsupported fields.

Native steering calls `turn/steer` with `expectedTurnId`, validates the acknowledgement, and keeps the existing turn identity. Steering cannot alter active turn settings. Fork starts a new connection session through `thread/fork`; `NativeForkBoundary::Turn` maps to inclusive `lastTurnId`. Legacy count rollback uses `thread/rollback` with `numTurns`; advertised paginated history instead requires `NativeRollbackBoundary::BeforeTurn`, mapped to `thread/revert` with `beforeTurnId`. Neither operation restores working files.

Canonical `reasoningEffort` maps to thread `config.model_reasoning_effort`, turn `effort`, and Plan `collaborationMode.settings.reasoning_effort`. Per-model values must come from native model discovery. Collaboration-tool and child-thread lineage preserve native references; known child terminal events become task events and cannot terminate the parent's turn. Wire fixtures cover steering preconditions, acknowledgements, RPC request-id collisions/errors, native history boundaries, effort mapping, and child isolation.

Turn attachments: images stay native `image` and `localImage` items, and every local attachment is also named in the text input with a line such as `[Attached file "spec.pdf" is saved at: /path]`, after the prompt. Non-image files reach Codex only through that line; Codex reads them with its own tools.

`thread/tokenUsage/updated` becomes canonical `thread.token-usage.updated`: the latest request's counts, `contextTokens` from `last.totalTokens` (the context the thread holds now, not the cumulative total) and `contextWindow` from `modelContextWindow`. Codex repeats its cached rate-limit snapshot on every token tick, so `account.rate-limits.updated` carries only the windows whose kind, used percent, reset time or duration changed since their last report; the host keeps the others.

`CodexProvider::spawn` wraps the app-server in `CodexProcess`, so an exit error quotes the stderr line that explains it, as T3 Code does: the last error-looking line (`Error: …`, `error[...]: …`, `fatal: …` or a tracing `ERROR` line) of the stderr tail, else its last line, without terminal controls and clipped to 512 characters. The shared transport's own error text is unchanged for other providers.
