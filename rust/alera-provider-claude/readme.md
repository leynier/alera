# provider adapter scope

This crate maps the shared provider contract to the Rust client for the streaming CLI. Host-owned MCP servers are projected into the SDK `mcp_servers` map: stdio uses `type`, `command`, `args`, and `env`, while HTTP uses `type`, `url`, and `headers`.

Injected server names cannot replace caller-owned entries. The native boundary does not represent a stdio working directory, so a spec that supplies one is rejected before launch. Only the trusted `alera` server receives the matching `mcp__alera__*` allowlist entry; other servers retain normal permission handling. Secret environment values and headers are not copied into provider events or debug output.

The projection is covered by lifecycle tests for exact native options, collisions, unsupported fields, and preservation of existing options.

Native fork uses the SDK's `resume`, `fork_session`, and optional `resume_session_at` on a fresh provider connection. `NativeForkBoundary::Message` is an inclusive native transcript UUID, retained as `payload.nativeMessageId` from full assistant messages; content/tool lifecycle ids are different references. A fork result does not claim a native id until Claude reports the new session identity. Generic conversation rollback and active turn steering remain unsupported.

`rewind_files` uses the SDK control request and requires `enableFileCheckpointing: true` at session launch. It restores checkpointed files only, without truncating conversation history. Canonical `reasoningEffort` maps to the verified SDK `effort` launch option (`--effort`); changing effort per turn is unsupported. Upstream `xhigh` is honored only with explicitly selected Opus 4.7, because other models fall back to high. Native task notifications and terminal update patches retain their task/tool/session references; absent native task ids remain warnings.

`native_history_capabilities.fileCheckpointing` reports launch-option support, while `rewindFiles` is true only on a live session launched with checkpointing enabled. Launch also requests replayed user messages. The provider keeps an optional `TurnInput.options.appUserItemId` locally and projects `payload.nativeUserMessageId` only when the parsed user frame's exact raw UUID matches a live submitted main prompt, app item, native session, and turn. Historical, synthetic, tool-result, and mismatched frames cannot create checkpoint correlation; assistant UUIDs remain separate fork boundaries. The host updates the original user item rather than appending a replayed echo.

Native file rewind returns optional native `canRewind`, error, file statistics, skipped-link count, and raw response for internal reconciliation. An empty acknowledgement does not confirm file restoration; `canRewind: false` and native error fields remain explicit outcomes. Public host views must allowlist observations rather than exposing raw provider responses.

Plan interaction is a session permission mode in Claude, so a turn whose `interactionMode` differs from the active one sends the SDK `set_permission_mode` control request before its prompt: `plan` for plan turns, and the launch permission mode (or `default`) for the next default turn. A main-agent `ExitPlanMode` tool use becomes a completed `plan` item carrying its Markdown, and its tool result never reopens it. While Alera's plan mode is active, the `ExitPlanMode` permission request is denied automatically with a message telling Claude to wait, because approving it would start editing in the same turn; outside plan mode it remains an ordinary approval. A main-agent `TodoWrite` tool use also emits `turn.plan.updated` with its `todos`, which the host normalizes into plan steps; sub-agent todos do not replace the main plan.

A turn fails when its result says so, even when the CLI reports an API error as a `success` result without `is_error`: any `error*` subtype, a listed error other than `[ede_diagnostic]` telemetry, an API status of 429 or 529, or one of the terminal reasons `api_error`, `malformed_tool_use_exhausted`, `budget_exhausted`, `structured_output_retry_exhausted`, `tool_deferred_unavailable`, `turn_setup_failed`, `blocking_limit`, `rapid_refill_breaker`, `prompt_too_long`, `image_error` or `model_error`. The failure message is Claude's own error text first, then a fixed sentence for the status or terminal reason.

Compaction is one `context_compaction` item, as Codex reports it: `system/status` `compacting` starts it, `compact_result` settles it as compacted or failed (`compact_error` is its detail), a `status: null` frame without a result or `permissionMode` stops it, and `compact_boundary` completes it with `data.preTokens` and `data.postTokens`, or reports a standalone item when no status frame came first. A compaction the turn ended during settles before the terminal event. Item `data` carries `trigger` (`auto`, or `manual` for a bare `/compact` prompt), `outcome` (`running`, `completed`, `failed` or `stopped`; a stopped compaction has status `failed`), `startedAt` and `completedAt`. `/compact`'s own assistant echo is dropped, and a `/compact` that a usage limit stopped fails its turn with the compaction error and failure class `usage_limit`, although the CLI ends it with a success result. Other status frames are dropped.

`system/api_retry` frames become one live `error` item per turn (`api-retry:{turn}`), titled "Provider retry" with `data.attempt`, `maxAttempts`, `retryDelayMs`, `errorStatus`, `error` and `code` (`api_error_{status}`, or the error name). The next assistant frame completes it as "Provider recovered"; a failed or interrupted turn settles it as failed. `system/informational` lines whose level is not `info`, such as a hook dropping the prompt, become notices with `preventContinuation`; `info` lines are dropped.

Each thinking block has its own `{messageId}:thinking:{n}` item, so a reply sharing the message id never lands in a reasoning item. For Claude 5.1 and later models, which write progress updates as thinking, the second of two non-empty thinking blocks right before that message's tool call is shown as assistant text.

Live context usage comes from root assistant snapshots and, when partial messages are on, from stream `message_start` and `message_delta` usage: `thread.token-usage.updated` carries `contextTokens` (input, cache and output tokens of the latest request), and `contextWindow` once a result's `modelUsage` named the model's window. Sub-agent and `<synthetic>` frames are ignored, and a compaction boundary reports its `post_tokens`. `autoCompactTokens` is reported only when `CLAUDE_CODE_AUTO_COMPACT_WINDOW` is set (and compaction is not disabled), as that window minus Claude Code's 33,000-token reserve, so with no configuration the meter shows no auto-compact tick. The turn's `tokenUsage` repeats the context fields.

A rejected rate limit that no overage covers reports its window at 100% with its reset time, both from a `rate_limit_event` without utilization and from a blocked assistant frame's `api_error_params.rate_limit_info`, which the CLI repeats while it throttles unchanged rate limit events.

Full Access asks Claude for `bypassPermissions`. When the Claude settings the CLI would read for the session (user, project, local, remote, managed and `managed-settings.d`, limited to the configured setting sources) set `permissions.disableBypassPermissionsMode`, the launch steps down to `auto`, or to `default` when `disableAutoMode` is also set; a settings file that exists but cannot be read or decoded counts as disabling bypass. A `system/init` that reports another mode than the bypass Alera asked for is adopted, and a default turn whose restore to bypass or auto the CLI refuses falls back to `default` instead of failing. Each case adds one notice, "Alera could not confirm Claude bypass permissions here, so Full Access is running with approval checks.", in the turn it affects. The session is never refused and the advertised runtime modes do not change, because the settings depend on the cwd and the CLI enforces them anyway.

`claude_settings_base_url` reads `env.ANTHROPIC_BASE_URL` from the user and managed Claude settings, later files winning, so the host can report a proxy endpoint that Claude's own account status cannot verify.
