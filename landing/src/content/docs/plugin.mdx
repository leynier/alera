## Prepare Your Runtime

<Steps>

1. [Install Alera](/download) and open it on the machine you want to connect.
2. Sign in under **Settings → Account**.
3. Open **Settings → MCP Access → MCP Control** and choose an access level. Read access is enough to inspect projects and agents. Full access lets the client launch agents and change workspaces. Keep Alera or its standalone runtime running while you use the plugin.

</Steps>

<Callout type="caution">
Full access allows the client to run commands on your machine. Choose runtimes and permissions in the OAuth connection flow. Administrative access is a separate choice; the plugin does not enable it automatically.
</Callout>

## Install The ZIP

The downloaded package works as a local plugin source for Codex and Codex in the ChatGPT desktop app. Client and workspace policies determine which plugin controls are available.

<Callout type="caution">
ChatGPT marks imported plugins with `mcp.json`, `.mcp.json`, or inline MCP declarations **Desktop only**, including remote HTTPS servers. This ZIP contains MCP configuration. Changing its transport or removing competing manifests does not provide web availability. See [OpenAI's desktop-only rule](https://learn.chatgpt.com/docs/enterprise/plugin-management#desktop-only-plugins).
</Callout>

<Steps>

1. Download **{PLUGIN_ARCHIVE}** and extract it. Keep the resulting **alera** folder intact, including its hidden `.agents` and `.codex-plugin` directories.

## Connect From ChatGPT On The Web

### Public Installation

Public users should install a published Alera listing and authorize their own account, without entering the MCP URL. This download is a package source; it is not an approved directory release or a web-install shortcut. Alera's public listing has not been verified by this packaging work.

The publisher must upload the MCP-and-skills ZIP to the [OpenAI submission portal](https://developers.openai.com/plugins/deploy/submission), verify the publishing identity and server domain, connect OAuth, resolve metadata, skill, and tool scans, provide review materials, submit for review, then publish after approval. Only the publisher performs server registration. Users still authenticate and choose their own runtime access. Publishing requires separate authorization; merging this repository does not publish the plugin.

OpenAI documents [directory search and direct listing links](https://developers.openai.com/plugins/deploy/app-review#discovery) after publication. The reviewed sources do not establish an unreviewed public or unlisted ZIP/link route for remote MCP plugins.

### Existing App References

For an app already available to the intended audience, OpenAI supports root `.app.json` references through `extensions.com.openai.apps` in `plugin.json`, or `apps` in the Codex compatibility manifest. Accepted IDs begin with `asdk_app_`, `connector_`, or `templated_apps_`. References create no app or permissions. A privately registered connection is not a public distribution solution. No app ID is embedded or invented here. See [existing-app references](https://learn.chatgpt.com/docs/enterprise/plugin-management#reference-an-existing-app-with-appjson) and [the package format](https://developers.openai.com/plugins/build/plugins#add-openai-specific-metadata).

### Developer Testing

You can connect the existing MCP server directly for a personal development test; this is not the public installation workflow:

<Steps>

1. Open [ChatGPT Plugins](https://chatgpt.com/plugins) and select **Add custom MCP server** from the plus menu.
2. Enter **Alera** as the name and use the endpoint below. Choose **OAuth** and complete the connection.
3. Select the resulting Alera plugin in a conversation and ask it to list your runtimes.

</Steps>

## Troubleshooting

| What You See | What To Check |
| --- | --- |
| Desktop only after ZIP import | Imported MCP declarations trigger this classification even with remote HTTPS. Web distribution requires the publisher's reviewed release, or references to apps already available to that audience. |
| No Alera plugin in the desktop directory | Check that the marketplace command points at the extracted `alera` folder, then restart the client. |
| No Alera tools | Install and enable the plugin, then complete its OAuth connection. |
| No reachable runtime | Open Alera, sign in to the same account, enable MCP Control, and check that the connection grants that runtime. |
| Insufficient scope | The connection grant and the runtime's MCP Control setting must both permit the requested action. Reconnect or change the runtime setting yourself if you want to grant it. |
| Multiple runtimes | Choose the returned runtime name or id. Each call targets one runtime. |

The plugin contains no account tokens or client secrets. Remote MCP arguments and results pass through Alera's cloud over TLS; they are not end-to-end encrypted. The service does not store those payloads. See the [Privacy Policy](/privacy) for data handling.
